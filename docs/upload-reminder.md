# 上报提醒

到点提醒"今天该上报会话了"，当天已经报过就不提醒。默认 18:00 / 19:00 / 20:00 / 21:00，可在 ⚙ 设置 →「上报提醒…」里改（整点九宫格 + 非整点输入框，多选）。

CLAUDE.md 只留了四条不看会踩的约束，这里是完整的。

## 判定分两半

| 函数 | 位置 | 性质 | 回答 |
|---|---|---|---|
| `dueReminders` | `upload-core.js` | 纯函数 | 现在到哪几个提醒点了 |
| `hasUploadedOn` | `upload-core.js` | 异步读 NAS | 某天报了没 |
| `checkUploadReminder` | `app/main.js` | 编排 | 要不要弹、弹什么 |

分开是为了能验：混成一个的话，跨天重置、开机后补发这些判据只能靠"等到那个点 + NAS 通着"来验，一天一次机会，且失败了看不出是哪条判据错的。

**没有宽限窗口是故意的**：看板 20:30 才开机时，18/19/20 三个点一起到期、合并成**一条**提醒（而不是补三条）——那正是你想知道的"今天还没报"。给宽限窗口的话，关着看板的那几个小时会把提醒整个吞掉。

## `ok` 与 `uploaded` 是两件事

不能合成一个布尔：

| 返回 | 含义 |
|---|---|
| `ok=true uploaded=true` | 报过了 |
| `ok=true uploaded=false` | 确实没报（盘读得到，就是没有今天的目录） |
| `ok=false` | **核对不了**（盘读不到 / 账号目录不存在 / 没账号）——不等于没报 |

域账号打错一个字母就会走到 `no_user_dir`，而错的方向偏"看起来正常"。所以读不到当天目录时要**逐层往上探**：账号目录在 → 可以断言没报；账号目录不在 → 不能断言；根也不在 → 更不能。少中间那一层，看板会一口咬定"今天没报"，而它其实什么都没看见（铁律 9 的同一类错误）。

`empty_day_dir`（目录在、一条 metadata 都没有 = 上报中途断了）按**没报**算：判成已报会让提醒当天彻底静默，而那恰恰是最需要提醒的一天。

## 三条产品决策

改之前先确认是不是真要改：

- **核对不上时照常提醒**，正文注明原因。静默跳过会让提醒整个失效而人不知道——一个看着开着、其实不响的开关比没有更糟。代价是在家没挂 VPN 的晚上会按设定的点数被敲几次，这是跟人明确确认过的取舍。
- **失败也要记账**（`markRemindFired` 在读 NAS 之后无条件调用）。不记的话下一个 30 秒周期立刻重来，断网的晚上会变成每半分钟一条通知。
- **当天核实"报过了"就收工**（`remindDoneDate`），当天不再读 NAS 也不再提醒。

## 频率

检查周期 30 秒，但**只有到点那一次才真读 NAS**，一天最多四次网络读。别挂到 `tick()` 上——那等于后台轮询共享盘，会破掉看板"无后台网络出口"这条性质（与上报窗口同一条纪律）。

`remindBusy` 是必需的，不是优化：SMB 挂住时一次读能拖十几秒，30 秒的周期会往上摞。

## 设置入口

时间是多选且允许非整点，原生菜单表达不了（Electron 菜单没有输入控件、`window.prompt` 被禁用），所以走自绘对话框——与自动删除阈值同一条路子，两个界面坑（自绘弹窗要自己挡按键）见铁律 6b。

**格式的权威只有 `upload-core.parseTimes` 一处**。渲染层把整点和输入框的内容拼成一个串原样送过去，连"逗号怎么切"都不自己决定；看不懂的条目由它回报 `{ok:false, dropped}`，页面只负责显示。两边各写一套正则的话，迟早出现"对话框收下了、落盘时被悄悄丢掉"。

有一条看不懂就整个不保存——半套生效比不生效更难查。

## 自检

```
node upload-core.js      # 纯函数 9 条断言 + 真实 NAS 的今日核对
```

主进程那段编排用一次性脚本验，做法是 stub 掉 `electron` 后用 `Module._compile` 载入**真正的 `app/main.js`**、只在尾巴上加一个测试出口——不复制一份逻辑来测（测副本等于什么都没测）。跑在临时 `CLAUDE_CONFIG_DIR` 下，碰不到真实 `ui-electron.json`。

`remindDoneDate` 是模块级缓存、一整天不失效，**换场景时必须显式清掉**，否则后面的用例全被它挡在门外，表现为一片 FAIL 而且原因看不出来（踩过）。
